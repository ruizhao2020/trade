# 交易概念文章结构

这个 skill 固化的是**概念/结构类**文章的写法：一个概念是什么、由什么组成、怎么算、在一个真实标的上怎么表现、和相邻概念什么关系。它不管指标形态目录；那类文章用 `indicator-article`。

## 先判断文章类型

- **概念/结构类**：缠论线段、中枢、背驰、走势类型，或道氏理论、波浪理论里的某个结构。文章的主线是“这个概念怎么定义、怎么算、怎么读”。
- **指标形态类**：一个指标有哪些形态、每个形态怎么判定、怎么调参。用 `indicator-article`。
- 两类文章都要配真实图表。配图流水线、画布合成、缓存与浏览器还原，沿用
  `.agents/skills/indicator-article/references/figure-pipeline.md`；文风扫描用
  `.agents/skills/indicator-article/scripts/style_scan.py`。

## 核心原则

1. **一条主线。** 全文只回答一个中心问题。小节是论证的台阶，不是知识点的堆叠。
2. **先拆后算，再看例子。** 先让读者知道这个概念由什么构成，再给算法，再用真实标的走一遍。不要一上来就贴公式或结论。
3. **案例必须有反直觉点。** 例如“段 1 为什么结束在 20.84，而不是最高的 24.81”。这个点是文章的骨架；没有它，案例只是把图上的线念一遍。
4. **图和正文分工。** 正文负责概念、条件和因果；图负责位置、颜色、编号和关键价位。正文不要提前说“图上”，图形编码放在图注里。
5. **纯概念。** 不暴露代码路径、函数名、接口名、系统名。读者不知道系统存在，只关心概念本身。
6. **允许不确定。** 结构方法有口径取舍，指标之间会矛盾。把矛盾写出来，比强行凑成“多指标共振”更可信。

## 七段骨架

这是参考骨架，不是逐字照搬的目录。标题按概念自然命名，但下面四类内容不能少：
**定义与构成、计算口径、真实案例、局限与风险**。

### 一、什么是 X

回答三个问题：

- X 在层级中的位置：它上面是什么、下面是什么。例：K 线 → 笔 → 段 → 中枢 → 走势。
- X 解决什么问题：它过滤掉了什么噪声，提供了什么更粗的视角。
- X 的用途：它被谁使用，能回答哪类问题，不能回答哪类问题。

配**图一：总览**。图上要有完整窗口、结构线、端点编号、关键价格。图注说明编号体系，并明确“X 不是唯一的”：换周期、换窗口、换阈值，结果会变。

### 二、X 由什么组成

自底向上拆原材料。每个组成部分写清：

- 定义；
- 最小条件（几根 K 线、几笔、几个元素）；
- 常见口径差异，以及本文采用哪一种、为什么。

如果概念依赖一个专门构造（例如线段的特征序列），单独用一小节讲它：取哪些元素、怎么做包含合并、合并方向是什么、出现什么形态算结束。

### 三、怎么算

把算法拆成阶段或步骤。每一步写清输入、判定、输出，不要只给结论。

- 分阶段时，先给每个阶段的目标，再给步骤。
- 关键阈值和参数用表格收口：参数、本文取值、含义、调大/调小后的后果。
- 最后用一句话回答：“一条 X 至少要能回答哪几个问题？”例：方向、起止端点、由哪些笔组成、是否已经确认结束。

### 四、案例：某标的某周期

先给结果表，再逐段解释。表格至少包含：结构编号、方向、组成、起点、终点、备注。表头要注明编号体系（笔序号还是端点编号），不要混用。

案例的子节顺序：

1. **反直觉点**：为什么端点不是最高/最低点。先把候选端点列出来，再逐条检查条件，最后说明被保留和被放弃的是哪一个。
2. **相邻案例**：另外几段为什么独立、为什么没有合并。用同一套条件解释，不要换一套说法。
3. **未完成/边界案例**：最后一段为什么还没确认，什么情况下会变。
4. **机制解释**：从资金、供需、持仓成本角度解释“为什么这里会结束”。明确这是解释，不是买卖信号；不要把它写成收益预测。
5. **指标间交叉验证**（可选）：只有拿到真实读数才写。每张图只放本节讨论的指标；先写读数，再写一致和矛盾。不要把交叉验证写成“每个指标都确认”的清单。

案例里的数字必须来自真实数据。图上的关键价位要用文字标出，标签不能压住 K 线、结构线或指标线。

### 五、X 与相邻概念

把 X 放回上一级或下一级结构里：

- 相邻概念怎么定义；
- 它和 X 的区别；
- 一个真实例子；
- 为什么两者不能互相替代。

配一张关系图。图注说明只保留了哪些图层，避免读者把示意图当成完整系统。

### 六、局限性

至少覆盖这几类，每类都要具体：

- 依赖级别和窗口：换周期、换窗口，结果会变；
- 方法是近似：哪些条件是取舍，原著/其他流派还有哪些分支没有展开；
- 端点不等于极值：结构终点和区间极值要分开看；
- 未完成状态会变：最后一段没有确认，新 K 线进来会改写；
- 相邻结构在样本少时很粗：段数少时，段中枢会变成一个很宽的盒子，不适合做精确位置。

### 七、风险提示

明确写：本文讲的是结构和一种口径，不构成投资建议；技术分析可能失效；实际决策要结合仓位、止损和风险承受能力。

## 配图规划

图号按**正文出现顺序**编号，不按文件名。新增图插在中间时，后面的图号整体顺延，文件名同步改，避免正文顺序和图号不一致。所有图统一 1242×882，和 `articles/images/` 现有图一致。

| 图 | 内容 | 注意 |
| --- | --- | --- |
| 图一 | 总览：完整窗口、结构线、端点编号、关键价格 | 图注说明编号体系和“口径不唯一” |
| 图二 | 案例局部：只画目标结构 | 关键价位用纯文字标注，不压线 |
| 图三、图四 | 机制/交叉验证：只放本节讨论的指标 | 讨论几个就画几个，不堆无关图层 |
| 最后一张 | 与相邻概念的关系 | 图注说明只保留了哪些图层 |

- 图上端点只用文字和颜色区分，不加图标；重合端点并排显示，中间用细竖线隔开。
- 价格标签用纯文字，无方框、无引线；放在空白处，不能覆盖 K 线、结构线、指标线或已有文字。
- 交叉验证图要先确定参照：顶背驰看零轴上方的红柱缩短，不是零轴下方的绿柱。绿柱通常是 DIF 下穿 DEA 之后的确认。
- 图注写清：窗口、颜色、线型、编号体系、关键价位、刻意省略了哪些图层。

## 写作约束

- **中文正文统一全角标点**，引号用 「 」，嵌套用 『 』；数字、日期、公式内部例外。
- **编号体系统一**：同一张表或同一段正文只用一套编号。笔序号和端点编号必须同时出现时，在首次出现处给出换算。
- **条件分支互斥**：写清「如果 A……；否则……」覆盖哪些情况；「它 / 这 / 前后两段」要有唯一指代。
- **结论落到可观察对象**：不写“更大的转折”“信号更强”“明显改善”这类没有参照的程度词。
- **不写 AI 味**：少用破折号、对偶句、段末金句；不用“值得”“本质上”“换句话说”“综上所述”。文风扫描应为 0 处英文标点、0 处弯引号。
- **交叉验证要写真读数**：先写每个指标的实际值，再写一致和矛盾。不要用“如果……就……”的空泛清单代替读数。
- **顶背驰的口径要写对**：标准顶背驰要求价格创新高、MACD 不创新高。价格是更低的高点、只是红柱缩短，只能叫“反弹动能减弱”。零轴下方的绿柱是动能转负的后续确认，不是顶背驰本身。

## 交稿前检查

- 七段是否齐全；案例是否正面回答了反直觉点；局限是否具体到可观察对象。
- 结果表的编号体系是否统一；共享端点是否说明；正文和表头是否混用 1-based 和 0-based。
- 图号是否按正文顺序连续；每张图是否只出现本节讨论的图层；价格标签是否压线。
- 案例数字是否与数据源一致；图注数字是否与图一致。
- `python3 .agents/skills/indicator-article/scripts/style_scan.py articles/<slug>.md --verbose`：
  英文标点 0、弯引号 0、破折号密度 <1、无框架/金句词。
- 全文搜索代码/系统词：`代码`、`系统`、`接口`、`函数`、`后端`、`signal-layer`。概念文章不应出现。
- 如果本轮改过代码：按仓库规则跑后端 pytest、前端测试、`npx tsc -b`。

## 示例

`references/chan-duan-example.md` 是 `articles/chan-duan.md` 的逐节拆解。写新文章前先读它，重点看：

- 反直觉点怎么组织；
- 两阶段算法怎么落到参数表；
- 案例之后怎么接“段中枢”；
- 交叉验证怎么写出真实读数，以及顶背驰口径怎么纠正。
