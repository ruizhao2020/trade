# 指标科普文章

这个 skill 固化的是本仓库 `articles/` 的写作流程：**先读代码核对口径 → 按固定结构写 → 用真实图表出配图 → 机械校验**。
每一步都来自实际踩过的坑，不要跳过校验步骤。

## 产出位置

```
articles/
├── README.md                    目录说明、写作约定、配图方法论（先读它）
├── <indicator-slug>.md          一篇文章（ASCII slug 文件名，中文标题写在正文里）
└── images/
    ├── fig-1-overview.png       图一：总览
    ├── fig-2-<form>.png         图二…：每个形态一张
    └── ...
```

- 图片**全部同一尺寸**（当前统一 1242×882），文章里按 `图一`、`图二`… 编号，用相对路径引用。
- 动笔前先读 `articles/README.md`：那里的写作约定是长期维护的，本文与之冲突时以 README 为准。

## 文章结构（七段参考）

> 如果写的是概念/结构类文章（例如缠论线段、中枢、背驰），不要套下面的指标七段结构，
> 改用 `trading-concept-article` skill；下面的骨架只适用于逐个形态讲指标的文章。

下面的结构是长期迭代出来的参考骨架，**不是要逐字照搬的目录**：

- 标题按逻辑自然命名，内容按论证需要调整；
- 但四类内容不能少：**定义与含义、计算口径、逐形态说明、局限与风险**；
- 不要把"推导关系"写进标题。曾出现过标题写成"由 1、2 推出为什么会有…"的情况——
  那是这一节与前两节的逻辑关系，读者不需要在目录里看到它。

1. **什么是量价/这个指标** —— 定义 + 形态一览 + 总览图（图一）
2. **意义及背后的市场含义** —— 用供需/努力与结果的框架解释"量"与"价"的关系
3. **为什么要有这个指标** —— 从"量价是什么、为什么重要"自然过渡到"必须把它做成可判定条件"。
   标题就写"为什么要有…"，不要写成"由 1、2 推出…"
4. **计算口径，参数怎么调** —— 窗口定义、关键量的算法依据、单根 vs 连续多根、各形态的判定表、参数表
5. **各形态分别说明** —— 每个形态：含义（白话）/ 口径（精确）/ 市场含义 / 配图
6. **局限性** —— 诚实的边界
7. **风险提示** —— 不构成投资建议

## 写作硬规则

- **只介绍指标本身。** 不写策略用法、参数组合示例、回测结论；除非用户明确要求。
- **不介绍站点/产品。** 最多提一句图表来自哪里，其余全部聚焦指标。
- **"根"必须说清是 K 线还是量柱。** 典型错误："当根之前的 20 根成交量"——应写成"当根 K 线之前 20 根 K 线的成交量"。
  涉及窗口时统一用"根 K 线"，涉及量能时用"量柱"或"成交量"。
- **中文正文统一用全角标点。** 引号统一用 「 」（需要嵌套时内层用 『 』），不要混用英文直引号 " " 或弯引号 “ ”；逗号、句号、分号、冒号、问号、感叹号、括号都用全角（，。；：！？（））；半角 `, . ; : ! ? ( ) [ ] " '` 只留给代码、公式、数字内部，并用反引号把技术记号包起来。日期里的连字符和数字的小数点不算混用。
- **参数表照抄代码**：默认值、取值范围、调大后的后果。不要凭印象写。
- **凡是"位置会改变含义"的设计，必须单独解释。** 例如"放量滞涨为什么必须带高位约束"——
  不加约束时，下跌途中的放量横盘（承接换手）会被误标成顶部预警。这类设计是文章最有价值的部分。
- **配图出现之前不要写"图上/图中的颜色"。** 图形编码（线色、线型、标记）放在对应图注里；正文先把概念讲清楚，再让图出现。确实需要提前指图时，写"后面的图一"，不要用没有参照的"图上"。
- **结论要落到可观察对象。** 不写"留下更大的转折""信号更强""明显改善"这类没有参照的程度词；读者会追问"更大是相对什么、转折指什么"。要么给出判定口径，要么换成具体对象，例如"用一段描述一轮更大的上涨或下跌"。
- **条件分支要写清互斥关系和指代。** 「如果 A……；否则……」必须说明「否则」覆盖哪些情况，三个以上分支就分条写；「它 / 这 / 前后两段 / 三条」要有唯一指代，合并、并入、跳过的对象和结果也要写清。反例：「如果它夹在两条同方向的线段之间，就把它和前后的线段合成一条；否则并入前一段。」读者会以为两个动作连续发生。
- **编号体系要统一并标注。** 同一张表或同一段正文只用一套位置编号：写「第几笔」就全文用笔序号，写「端点编号」就全文用端点编号；表头注明是哪一套。必须同时出现时，在首次出现处给出换算（第 k 笔的终点 = 端点 k；端点 1 = 第 2 笔的起点），不要在同一列混用 1-based 和 0-based。反例：同一列里段 1 写 2–16（笔序号），段 2 写 16–23（端点编号）。
- **不写收益、胜率、"稳赚"**；结尾必须有风险提示。
- 图上颜色、方向、标记的说明必须与实现一致（买入侧红 `#ff5b62` / 卖出侧绿 `#2fc58d`）。
- **文风层与内容层分开处理。** 担心"AI 味重"时，只改标点与连接词——
  破折号密度、"一句话 / 换句话说 / 简单来说"、段末金句（"这正是…的原因""才是真正的…"）这些。
  **不要碰**口径、数字、限定条件、术语、图注与风险提示。
  例：把"连续 3 根、每根相对量能 ≤ 0.7"改写成"量能连着几天都萎了"，味道是没了，指标也没法看了。

## 工作流

### 1. 读代码，先把口径搞清楚

不要先写文章再对代码。按这个顺序读：

| 读什么 | 为什么 |
| --- | --- |
| `signal-layer-server/app/engine/indicator/<type>.py` | 判定条件、参数、校验范围、markers 与颜色 |
| `signal-layer-server/app/api/indicator.py` 的 `INDICATOR_META[<type>]` | default_params、outputs（含 `kind=event`）、description |
| `tests/test_engine/test_<type>.py` | 口径的真实边界（测试里的反例最能说明设计意图） |

然后用脚本**机械比对**文章里的数字与代码（默认值、范围、比较运算符），不要靠人眼：

```bash
cd signal-layer-server && python3 -c "
from app.api.indicator import INDICATOR_META
import json; print(json.dumps(INDICATOR_META['<type>'], ensure_ascii=False, indent=2))"
```

### 2. 写正文

按上面七段结构写。第 5 段每个形态的四个部分要齐：**含义 / 口径 / 市场含义 / 图**。
口径里把"几根 K 线"、"当根之前还是含当根"、"单根还是连续"都写死。

### 3. 出配图

**先读 `references/figure-pipeline.md`**，按里面的步骤与代码执行。要点：

- 先用 `scripts/find_window.py` 扫出一个"所有形态都有实例、两两间隔足够"的标的与窗口；
- 浏览器里把行情与指标值**一起截到该窗口**，每张图只注入目标形态的标记（真实配色 + 非空 `rule`，否则文字不加中括号）；
- 合成时按 canvas 的真实偏移（含价格轴、时间轴），输出尺寸写死；
- 用**颜色占比**验证标记的方向，不要用像素差；
- 结束后还原浏览器现场。

### 4. 校验（不能省）

```bash
# 文章：标题结构、图片链接、表格列数、图注编号连续性
python3 - <<'PY'
import pathlib, re, struct
text = pathlib.Path('articles/<slug>.md').read_text(encoding='utf-8')
refs = re.findall(r'!\[[^\]]*\]\(([^)]+)\)', text)
for r in refs:
    p = pathlib.Path('articles') / r.lstrip('./')
    assert p.exists(), r
    w, h = struct.unpack('>II', p.read_bytes()[16:24])
    print(r, f"{w}x{h}")
PY
```

- 所有图尺寸一致；
- 图注编号 `图一…` 连续且与正文引用顺序一致；
- 叙述顺序：正文有没有在配图出现前写“图上/图中”？有没有“更大的转折/更强的信号”这类没有落点的结论？有就移到图注或换成可观察对象；
- 标点：中文正文的引号、逗号、括号等是否为全角；引号统一用 「 」（嵌套用 『 』），`style_scan.py` 的“英文标点”和“弯引号”都应为 0 处；公式和代码用反引号包裹，不要为了通过检查改数字；
- 歧义：每个「如果 / 否则」是否互斥且覆盖完整？「它 / 这 / 前后两段 / 三条」是否只指一个对象？合并、并入、跳过的对象和结果是否写清？
- 编号：表头和正文是否用同一套编号（第几笔 / 端点编号）？共享端点是否说明？同一列有没有混用 1-based 和 0-based？
- 若本轮改过代码：后端 `python3 -m pytest`、前端 `npm test -- --run` + `npm run lint` + `npx tsc -b` + 双构建。

**文风体检**（读者反馈"AI 味重"、或准备对外发布时）：

```bash
python3 .agents/skills/indicator-article/scripts/style_scan.py articles/<slug>.md --verbose
```

看五项：破折号密度（每千字 <1 较自然）、框架/金句词命中、英文标点（应为 0 处）、弯引号（应为 0 处，统一用 「 」）、句长变异系数（0.45~0.65）。

“英文标点”不是 0 时，按行号把正文里的半角标点改成全角；“弯引号”不是 0 时，把 `“ ”` 改成 `「 」`（嵌套用 `『 』`）。公式、代码、路径用反引号包起来，**不要为了通过检查改数字或术语**。
按命中项**定点**改标点与连接词，然后：
1. 重跑扫描确认指标下降；
2. **回归检查内容层**——口径片段、参数数字、图片链接、图注编号一个都不能变。

句长变异系数只作参考，不要为了数值好看强行改节奏。同构感常常来自"每段都用同样的方式开头"，
而不是句子长短。

### 5. 交付说明

必须写清**哪些是验证过的、哪些没有**：

- 数字与代码的一致性、图片尺寸/非空/颜色方向 —— 程序化验证过；
- **构图好不好看、标签挤不挤 —— 看不到图，无法判断**，明确请人过目；
- 浏览器现场已还原（令牌已清、回到登录页、视口还原）；
- 用户数据未被改动（例如 `GET /api/v1/templates` 数量不变）。

## 常见陷阱

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 截图超时 / 空白 | 浏览器截图通道在图表有数据后不可用 | 改为导出图表 canvas（见 reference） |
| 蜡烛只占宽度一小块 | 只切了行情没切指标值，时间轴取了并集 | 行情与指标值**必须一起切** |
| 窗口改了但图没变 | 前端行情缓存（日线 TTL 5 分钟）绕过了拦截 | 换一个新标的拿冷请求；同标的 5 分钟内别改窗口 |
| 拖拽缩放立刻被还原 | 数据更新触发 `fitContent()` | 不要用拖拽缩放，改用窗口切片 |
| 同一篇文章图片大小不一 | devicePixelRatio 在 1x/2x 之间跳 | 输出尺寸写死，不按 dpr 缩放 |
| 标记描边发紫 | "注成品红再还原"无法还原抗锯齿边缘 | 直接注入线上真实配色 |
| 卖出侧箭头是红的 | 总览图所有形态共用了买入侧配色 | 每个形态按自己的买卖侧取色 |
| 像素差验证差值巨大 | 两次抓图未像素对齐（dpr 变化） | 改用颜色占比验证 |
| 读者说"AI 味重" | 破折号过多、框架词/金句收尾、对偶句式密集 | 用 `style_scan.py` 定位，只改标点与连接词；口径、数字、图注不动 |
