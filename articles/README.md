# 指标科普文章

这个目录放**面向外部读者的指标科普文章**：讲清楚一个指标由什么组成、怎么算、
背后是什么市场逻辑。用途有两个——对外做内容推广，对内作为"这个指标到底实现了什么"
的说明。

文章不是接口文档。接口字段、参数范围以代码为准；文章负责把代码里的取舍讲明白。

## 写作约定

1. **每篇覆盖四段**：由什么组成、每个部分是什么意思、具体怎么算、背后的市场意义。
   少一段读者就会只记住结论、不知道边界在哪。
2. **计算部分要和代码对齐**，并写清楚对应的实现位置（如
   `signal-layer-server/app/engine/indicator/volume_price.py`）。
   代码改了而文章没跟上时，靠这个路径能找到该改哪里。
3. **参数默认值和取值范围照抄代码**，不要凭印象写。读者会拿这些数去调参。
4. **文件名用 ASCII slug**（如 `volume-price-indicator.md`），标题用中文写在文件里。
   推广时要用到 URL，中文文件名在多数渠道里会被转义成一串编码。
5. **必须写边界与风险提示**。技术指标只说"这个形态在量价关系上意味着什么"，
   不承诺收益、不构成投资建议。这类文章一旦被当成荐股，性质就变了。
6. 不写"胜率 xx%""稳赚"这类表述。要举例子就举**判定逻辑**的例子，不举收益。
7. **配图必须是真的图表渲染**，不要用示意图假装。配图放在 `images/`，
   文章里按 `图一`、`图二`… 编号，用相对路径引用。
8. **所有配图裁成同一尺寸**（本目录统一 1242×882），否则排版会参差。

## 配图怎么来

图片放在 `images/`，是**从真实运行的图表里导出的**，不是画的示意图。做法：

1. 本地起服务（`./start-private.sh`），登录后选好品种与周期，把要讲的指标加到图上。
2. 导出：**别用浏览器截图**。图表一旦有数据，截图通道就会超时（实测多次）。
   可行的是在页面里把图表自己的 canvas **按各自在容器里的真实偏移**合成到一张
   offscreen canvas（每个 pane 一行 + 底部时间轴，注意 devicePixelRatio），再 `toDataURL`
   写成 PNG。逐张 `drawImage(c, 0, 0)` 会把价格轴画到图表左边，是错的。
   **输出尺寸要写死**：devicePixelRatio 在不同次渲染间会变（同一次会话里 1x / 2x 都出现过），
   按 dpr 缩放会让同一篇文章的图大小不一。

3. **窗口要自己定，别靠拖拽缩放**。拖拽缩放会被"数据更新 → `fitContent()`"冲掉，极不稳定。
   可靠做法是在页面里拦截 `/klines`，把返回的 K 线**截成目标下标区间**；同时拦截
   `/indicator/calculate`，把 `values` **按时间切到同一段**——两边必须一起切，
   否则时间轴会取所有序列的并集，K 线只占宽度的一小块。
   另外**先把缠论图层关掉**：它是 500 根长度的独立序列，会把时间轴硬撑回 500 根。
4. **前端有行情请求缓存**（`api/requestCache.ts`，日线 TTL 5 分钟，key 含 symbol/timeframe/limit）。
   被缓存的响应会绕过页面里的一切拦截，所以：**换一个新的标的**可以拿到新鲜的 K 线请求；
   同一标的 5 分钟内不要再改窗口参数。指标计算的响应也会被缓存，改注入内容后
   用"切周期再切回来"触发一次重算即可。
5. **每张图只显示目标形态的标记**：拦截 `/indicator/calculate` 的响应，把 `render.markers`
   替换成只含目标形态的一条（颜色临时改成品红，便于按像素定位与核对），
   合成后把品红按买卖侧还原成真实配色（`#ff5b62` / `#2fc58d`）再存盘。
   这样一张图里只有一个（或该形态自己的几个）箭头，读者不会看错说的是哪一个。

**两个必须说清的局限**：

- 写文章的 agent **看不到图片**（模型不支持图像输入，子代理同样不行），所以只能程序化核对：
  尺寸、是否空白、包含哪些颜色、标记是否落在预期区域。**构图好不好看、标签挤不挤，只有人能判断**，
  图生成后要人工过一眼再发出去。
- 上面第 5 步是"只显示目标形态"的**示意性精简**——线上是七个形态一起标的。
  图注里要能看出这一点（例如"每张图只显示该形态的标记"）。
